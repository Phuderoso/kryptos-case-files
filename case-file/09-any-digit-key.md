# 09 — "Change the base": any small-digit key, any generator (cycle 11)

> *Cycle 10 asked whether Gromark's Fibonacci digits did it. This time I dropped the question of where the digits come from. If the key is made of small digits, whatever produced them, the cribs have to show it.*

## Idea
Many readings of Sanborn's "change the base" hint come down to a key made of **digits in base b ≤ 10**: Gromark, a number written in another base, dates, coordinates, Berlin-clock lamp counts (base 5), and so on. Every one of these is a special case of one model:

  c_i = CA[(PA⁻¹(p_i) + s + d_i) mod 26]   (Vigenère form; Beaufort is CA⁻¹(c_i) = s + d_i − PA⁻¹(p_i); variant Beaufort is Vigenère negated)

where **d_i ∈ {0…b−1} comes from any source** and s is an unknown alphabet rotation. With the 24 known plaintext letters, the 24 offsets CA⁻¹(c_i) ∓ PA⁻¹(p_i) must all fit inside a **cyclic window of width ≤ b**. The test doesn't depend on how the key was generated. That makes it much broader than cycle 10, which only covered lagged-Fibonacci keys with primers of length 4–6.

## Search (`tools/digitkey_dump.py`, `tools/c/digitwin.c`)
- **Alphabets:** 86,731 distinct ones. That's the cycle-10 set (AZ, KA, ZA, plus keyed, reversed-keyed and ACA-columnar alphabets from every 3–14-letter word in the Gutenberg vocabulary and the plain-sight words), **plus multi-word keyphrases**: every ordered pair of the 89 plain-sight words (e.g. SHADOW+BERLIN, LUCID+MEMORY, PALIMPSEST+NORTHEAST), in keyed, reversed and columnar forms.
- **Coverage:** each alphabet is tried as the plain alphabet and as the cipher alphabet, so 7.52×10⁹ pairs, in 2 modes. That's 1.5×10¹⁰ exact tests in C/OpenMP, which took 31 s on 8 cores.

## Result (`analysis/digitkey_report.txt`)
| window width (≈ base) | K4 Vigenère | K4 Beaufort | expected by chance, per mode |
|---|---|---|---|
| ≤ 8 | 0 | 0 | 0.10 (w=8) |
| 9 | 1 | 1 | 1.61 |
| 10 | 14 | 16 | 19.76 |

- The hit counts match chance exactly. The surviving pairs are unrelated words (e.g. c:BULLIES / k:UBIQUITY, c:EFFULGENT / k:TECHNICALLY). No pair of Kryptos-themed words stands out.
- **None of the 32 hits is consistent with a lagged-Fibonacci (Gromark) generator.** That was checked for L = 1–8, bases 9–10 and every offset, inside the two consecutive crib blocks (`tools/digitkey_followup.py`).
- **No digit key in base ≤ 8 (including the Berlin clock's base 5) works with any keyword or two-word-keyphrase alphabet pair.** That holds whatever produced the digits.

## Controls (`analysis/digitkey_control.txt`)
- **C1 and C2:** I planted the digits of π (not generated by any recurrence) with PA = keyed(LANTERN), CA = keyed(SHADOW+BERLIN), s = 7, once in Vigenère and once in Beaufort. The exact pair was recovered, along with its exact 24 digits.
- **C3:** I planted a true Gromark key (primer 27182, base 10, L = 5). It was recovered, and the Fibonacci follow-up flags it (L = 5, base 10), together with its mathematically equivalent reversed-alphabet Beaufort form.

## Interpretation (labelled)
- **Fact:** a key of small digits (base ≤ 8) combined with any keyword or two-word-keyphrase alphabets is excluded for K4 as carved, read straight with no transposition.
- **Fact:** for base 9–10 the survivors are exactly what chance predicts, and none of them is Gromark-like.
- **Limit:** a transposition layer applied before or after would move the cribs, and this test assumes they sit in place. Arbitrary (non-keyword) alphabets aren't covered. Sanborn's "scrambled plain text" remark (cycle 2) still points to a transposition layer, which is the natural next composition: undo a transposition, then run the same window test.
