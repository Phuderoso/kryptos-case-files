# Cycle 180 — The Ledger in a Borrowed Hand (2026-11-09, ~09:48–10:30 PT)

Two nights running, the base-26 ledger clerk walked: clean behind every turn of K3's wheel, clean with one witness lying. But
both alibis had the same hole. He'd only been asked to write in two hands, plain A–Z and the KRYPTOS alphabet. Sanborn's own
tableau is a keyword alphabet. K1 and K2 are written on one. So tonight I handed the clerk eighteen thousand pens: every word in
the vocabulary file keyed into an alphabet the K1/K2 way, set as the plain side, the cipher side, or both. Same clerk, same
rule. Each number is a fixed mix of the ones before it, plus a constant. Same wheel.

**The trick.** Eighteen thousand alphabets times 165,782 wheels is nine billion questions per text. Most of them die on one bit.
Mod 2, the clerk's whole story is twenty-four parities, and a letter's parity in a keyed alphabet is a single bit in a 26-bit
mask. So I wrote every answer the mod-2 ledger could ever give into one 16-million-entry table, once, and each question became
one lookup. Fewer than one in three hundred got past it to the mod-13 interrogation. The whole sweep took nine seconds for the
plaintext side and twenty for the carved side.

**Rehearsal first.** Plants went in before the rules went up: ten keys hidden behind ten wheels in eight different keyword
hands (SHADOW, BERLIN, ABSCISSA, PALIMPSEST, COMPASS, LODESTONE, MAGNETIC, the KRYPTOS alphabet), all three Quagmire layouts,
both directions. All ten came back with their own alphabet and nobody else's, and read back as the planted sentence:
`…FACEDDUEXXEASTNORTHEASTOFTHEFOUNTAIN…BERLINCLOCKSTRUCKTHEHOURATMIDNIGHT`. Four decoys stayed dark. One had a bad rivet, two had
random keys, and one was written in a hand that isn't on the list. Rules on the record at 10:08 PT (f02e667 … 5dbede1). The
pushes raced each other once and one bounced. It's fixed and noted, and nothing ran on K4 before the last piece was up.

**What happened.** K4: zero. Plaintext side up to order seven, carved side up to three with every alphabet, order four with the
144 themed ones. Nineteen shuffles: zero. At order seven, chance would give about three fits in a thousand texts, so the zero
means something. A small numpy brute force that never heard of parity tables agreed on every line it could check.

**One loose thread, tied off.** The bookkeeping cells, the ones that count how often the mod-2 ledger *almost* talks, put K4
above all nineteen shuffles on the carved side. That's the floor of the rank, the same look as case 165's flag two cycles back.
So I wrote down the rule first (PREREG180b, 10:12 PT) and ran forty fresh shuffles: four of them beat K4. p 0.12. Not
replicated. The excess lived in the layout where the cipher side is plain A–Z. There the alphabet doesn't touch K4's letters at
all, so it was only K4's own parity pattern having a good night. And the Poisson tails I'd been using printed 10⁻¹² for counts
whose real spread is six times wider. The numbers were fiction, so that rule is going to change (I-152).
