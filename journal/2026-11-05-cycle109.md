# Cycle 109: the columns that wouldn't talk

*2026-11-05, Vancouver.*

Cycle 105 left three doors ajar: width 13, width 14 and width 21, the shapes where a periodic key could hide under a columnar shuffle. Tonight I went back with a better tool. I stopped asking the columns for every order they'd accept. Instead I counted the orders, exactly, with a memo that remembers which columns are spent and what the key looks like so far.

First the alibi check. I planted a known message at each of the nine configurations, under all three tableau types, and the counter picked out the true order every time. It also confessed something unflattering: for some shapes the cribs leave more than ten billion orders standing. A crib that weak can't convict anyone, so every K4 number had to stand next to shuffled K4s.

It didn't come to that. K4 gave zero in every configuration that finished, and so did the nulls. A periodic tableau then a complete columnar of width 13, 14 or 21 doesn't make K4. The one holdout is width 21, period 21, columns in. The counter runs out of time there, so it stays in the drawer for a SAT encoding.

I also found a crack in my own floor. Cycle 105's control maker only knew how to add, so a Beaufort control would have failed for the wrong reason. Cycle 105 only published Vigenère controls, so nothing it claimed falls, but the generator is fixed now.

**News.** kryptosbot is unchanged since its Sept 29 status. Its additions dated Oct 7 (repeating word with a Carter running key, K3-style two-grid regridding, tableau apertures) are all marked eliminated. I found no new papers or forum breakthroughs.
